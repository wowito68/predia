Objetivo:
Tener comandos rapidos para demostrar seguridad, API, SSL, firewall,

pide credenciales, usalas solo en tu terminal local y no las proyectes.

bash scripts/demo/ssh-access-doctor.sh allow-private-anywhere
# MODO DEMO URGENTE: abre SSH 22 desde cualquier red en el Security Group

#
# Si no tienes AWS CLI, hazlo en consola AWS:
# EC2 > Security Groups > sg-0cfbdcb57a224f9a5 > Edit inbound rules
# Add rule: SSH | TCP | 22 | Source 0.0.0.0/0
# Description: PREDIA demo SSH temporal any network

bash scripts/demo/ssh-access-doctor.sh revoke-private
# Cierra la regla temporal de SSH para tu IP actual despues de presentar.

bash scripts/demo/ssh-access-doctor.sh revoke-private-anywhere
# Cierra la regla 0.0.0.0/0 del Security Group privado al terminar la demo.

# En consola AWS:
# EC2 > Security Groups > sg-0cfbdcb57a224f9a5 > Edit inbound rules
# Borra la regla SSH 22 con Source 0.0.0.0/0.

sudo bash infra/firewall/demo-anywhere-ssh.sh enable
# Ejecutar dentro del VPS si UFW tambien estaba limitado a una IP vieja.
# Permite SSH desde cualquier red con rate limit, manteniendo password/root off.

2. PRUEBAS RAPIDAS DESDE TU MAQUINA LOCAL
===============================================================================

curl -I "http://${PREDIA_DOMAIN}"
# Debe responder 301 hacia HTTPS. Prueba redireccion segura.

curl -I "https://${PREDIA_DOMAIN}"
# Debe responder por HTTPS. Prueba que el sitio tenga certificado SSL activo.

curl -fsS "https://${PREDIA_DOMAIN}/api/ready"
# Prueba readiness real de la API. Incluye conexion a base de datos.

curl -fsS "https://${PREDIA_DOMAIN}/api/health"
# Prueba health basico de la app web/API.

curl -fsS "https://${PREDIA_DOMAIN}/mobile/healthz"
# Prueba que la version movil web este publicada detras del proxy.

curl -sS -o /dev/null -w "%{http_code}\n" "https://${PREDIA_DOMAIN}/api/pacientes"
# Sin JWT debe responder 401. Demuestra proteccion de API.

for i in $(seq 1 12); do curl -fsSI "https://${PREDIA_DOMAIN}/api/health" | awk -F': ' '/X-PREDIA-Instance/{print $2}'; done | sort | uniq -c
# Muestra que el balanceador reparte respuestas entre replicas distintas.

for i in $(seq 1 60); do curl -s -o /dev/null -w "%{http_code}\n" "https://${PREDIA_DOMAIN}/api/health"; done | sort | uniq -c
# Envia varias solicitudes seguras para demostrar disponibilidad y estabilidad
# sin hacer una prueba destructiva de carga.

openssl s_client -connect "${PREDIA_DOMAIN}:443" -servername "${PREDIA_DOMAIN}" </dev/null 2>/dev/null | openssl x509 -noout -issuer -subject -dates -fingerprint -sha256
# Lee el certificado TLS servido en vivo: emisor, dominio, vigencia y huella.

5. SERVIDOR PUBLICO: ESTADO, LOGS Y RECUPERACION RAPIDA
===============================================================================

ssh -i "$HOME/Descargas/PREDIA.pem" "$PREDIA_PUBLIC_SSH"
# Conectarse al VPS publico.

cd ~/predia
# Ir al proyecto desplegado en el servidor publico.

docker compose -f docker-compose.production.yml ps
# Ver estado de API, proxy, movil web, DB y exporters.

docker compose -f docker-compose.production.yml logs --tail=80 predia-proxy
# Ver ultimos logs de Nginx/reverse proxy.

docker compose -f docker-compose.production.yml logs --tail=80 predia-api-1 predia-api-2
# Ver ultimos logs de las replicas de la API.

docker compose -f docker-compose.production.yml logs --tail=80 predia-mobile-web
# Ver logs de la version movil web servida por Nginx.

docker compose -f docker-compose.production.yml restart predia-proxy predia-api-1 predia-api-2 predia-mobile-web
# Reinicio rapido si la web/API/movil web se queda colgada.

docker compose -f docker-compose.production.yml up -d --build
# Reconstruye y levanta produccion. Usar si acabas de subir cambios.

docker stats --no-stream
# Muestra uso actual de CPU/RAM por contenedor.

df -h
# Revisa espacio en disco. Si esta lleno, Docker o MySQL pueden fallar.

free -h
# Revisa memoria disponible del servidor.

sudo journalctl -u docker --no-pager -n 120
# Logs recientes del servicio Docker si los contenedores no levantan.

12. FRASES RAPIDAS PARA CONTESTAR
===============================================================================

"El servidor publico solo expone 80 y 443; la base de datos y Grafana estan en
red privada o enlazados a localhost."

"La API no acepta endpoints clinicos sin JWT. Si llamamos /api/pacientes sin
token, responde 401."

"El balanceador es Nginx y distribuye peticiones entre predia-api-1 y
predia-api-2; lo comprobamos con la cabecera X-PREDIA-Instance."

"Las validaciones importantes no dependen solo del formulario: tambien estan
en backend. Por eso un curl con peso 999 kg o cita pasada responde 400 y no se
inserta en la base de datos."

"Grafana no esta publico; entramos por tunel SSH para monitoreo administrativo."

"Antes de migrar o redeployar, se debe correr backup y revisar migraciones."
